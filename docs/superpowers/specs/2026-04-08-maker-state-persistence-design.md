# Maker Bot State Persistence & Continuation Design

**Date:** 2026-04-08  
**Status:** Approved  
**Scope:** Market continuation — resume inventory/P&L across restarts, lifetime fill ledger, enhanced dashboard

---

## Problem Statement

The maker bot currently holds all state in memory. Every restart loses:
- Inventory positions per token (circuit breakers and skew start blind)
- Cash P&L, realized P&L, FIFO lots (daily loss limit resets, can breach limit post-crash)
- Fill/cancel counters, quote uptime (metrics meaningless across restarts)
- No lifetime fill ledger (can't analyse per-market performance)

---

## Goals

1. **Within-day resume** — after a crash or planned restart, bot picks up correct inventory, P&L, and daily loss limit state
2. **Lifetime ledger** — every fill is durably recorded; total and per-market performance is queryable at any time
3. **Dashboard split** — session / today / all-time metrics visible side by side with per-market breakdown table

---

## Non-Goals

- No database dependency (SQLite, Postgres, etc.)
- No changes to QuoteEngine, OrderManager, MarketSelector, or MarkoutTracker
- No real-time replication or remote storage

---

## File Layout

```
maker_data/
```

## Data Structures

### maker_checkpoint.json

Written atomically (write to `.tmp` → `os.replace()`). Loaded on startup. Contains full
in-memory state so the bot can resume without replaying all history.

```json
{
  "session_id": "2026-04-08T13:15:36",
  "checkpoint_at": 1775550000.0,
  "inventory": {"10991849": -12.4, "93471119": 3.1},
  "cash_pnl": 14.23,
  "realized_pnl": 2.11,
  "total_fills": 847,
  "total_cancels": 3201,
  "uptime_ticks": 1420,
  "total_ticks": 1500,
  "open_lots": {"10991849": [[0.25, 10.0], [0.26, 5.0]]},
  "daily_fills_seen": ["fill-id-1", "fill-id-2"]
}
```

`daily_fills_seen` is the set of `fill_id`s already processed this calendar day — used to
deduplicate fills when replaying the daily fill file on startup.

### maker_fills/maker_fills_YYYY-MM-DD.jsonl

One JSON line per fill. Appended immediately when a fill is processed by InventoryManager.
New file created at UTC midnight (daily rollover).

```json
{
  "fill_id": "paper-10991849-buy-0.2500-1775550001",
  "session_id": "2026-04-08T13:15:36",
  "ts": 1775550001.0,
  "token_id": "10991849",
  "question": "Will Iran regime change by 2027?",
  "side": "BUY",
  "price": 0.25,
  "size": 10.0,
  "cash_flow": -2.5,
  "realized_pnl": 0.0,
  "inventory_after": -12.4
}
```

`fill_id` format: `{mode}-{token_id_prefix}-{side_lower}-{price:.4f}-{ts_int}`

### maker_lifetime.json

Aggregated cache. Updated at session clean shutdown and at daily rollover. If missing or
corrupted, regenerated by `scripts/rebuild_lifetime.py` from all daily fill files.

```json
{
  "last_updated": 1775550000.0,
  "total_fills": 12480,
  "total_realized_pnl": 38.42,
  "total_cash_pnl": 22.10,
  "by_market": {
    "10991849": {
      "question": "Will Iran regime change by 2027?",
      "fills": 240,
      "realized_pnl": -3.1,
      "cash_pnl": -2.0,
      "avg_markout_30s": -0.002
    }
  },
  "by_date": {
    "2026-04-08": {"fills": 847, "realized_pnl": 2.11, "cash_pnl": 14.23},
    "2026-04-07": {"fills": 1203, "realized_pnl": 8.40, "cash_pnl": 6.12}
  }
}
```

`avg_markout_30s` in `by_market` is populated from `fills_markout.jsonl` data already
tracked by MarkoutTracker — merged into lifetime stats at session close.

## Startup & Resume Logic

`MakerStateLoader.load(maker_state, mode)` is called in `maker/runner.py` before any
actor starts. Steps in order:

1. **Load checkpoint** — if `maker_checkpoint.json` exists, restore all fields into
   `MakerState`. Log restored inventory totals and P&L.

2. **Replay today's fill file** — open `maker_fills/maker_fills_YYYY-MM-DD.jsonl` (today's
   date). For each line, if `fill_id` not in `daily_fills_seen`, re-apply via
   `MakerState.record_fill()` and add to `daily_fills_seen`. This recovers fills that
   arrived in the <60s window after the last checkpoint.

3. **Load lifetime stats** — load `maker_lifetime.json` into `MakerState.lifetime_stats`.
   If file is missing, run inline rebuild from all daily fill files (scans once, then saves).

4. **Live-mode reconciliation** (only when `PAPER=false`) — query CLOB API for open orders
   and recent fills. Compare against checkpoint inventory. Log any discrepancies as
   WARNINGs. Trust CLOB API as ground truth; patch `MakerState.inventory` accordingly.

5. **Set session_id** — `datetime.utcnow().isoformat(timespec='seconds')`.

## Checkpoint Writer

Runs as an `asyncio` background task in `maker/runner.py`, alongside the six existing
actor tasks. Interval: 60 seconds.

```python
async def _checkpoint_loop(maker_state, path="maker_data/maker_checkpoint.json"):
    while True:
        await asyncio.sleep(60)
        MakerCheckpointer.write(maker_state, path)
```

Atomic write pattern:
```python
tmp = path + ".tmp"
with open(tmp, "w") as f:
    json.dump(snapshot, f)
os.replace(tmp, path)   # atomic on POSIX and Windows
```

## Fill Ledger

`FillLedger` is instantiated in `maker/runner.py` and passed to `InventoryManager`.
After `MakerState.record_fill()` in `InventoryManager.handle_fill()`, call:

```python
fill_ledger.append(fill, maker_state)
```

`FillLedger.append()`:
- Builds the fill record dict (fill_id, session_id, ts, token_id, question, side, price,
  size, cash_flow, realized_pnl, inventory_after)
- Appends one JSON line to today's file
- Checks if UTC date has rolled over; if so, flushes old file handle and opens new one

---

## Clean Shutdown

`maker/runner.py` registers a shutdown handler (via `asyncio` task cancellation catch or
`signal.signal`). On shutdown:

1. Write final checkpoint (`MakerCheckpointer.write()`)
2. Merge session stats into `maker_lifetime.json` (`LifetimeStatsUpdater.merge()`)
3. Log `"Maker state saved cleanly — fills={n}, realized_pnl={p:.2f}"`

If process is killed hard (no shutdown handler runs), the next startup's fill-file replay
recovers any fills missed since the last 60s checkpoint.

---

## Daily Rollover (mid-session midnight)

`FillLedger` tracks current UTC date. On each `append()` call, if the date has changed:
1. Close the old file handle
2. Open a new file for the new date
3. Call `LifetimeStatsUpdater.merge_date(old_date, maker_state)` to flush yesterday's
   session contribution into `maker_lifetime.json["by_date"]`

## Dashboard Changes

### Top-level P&L bar (replaces single P&L line)

Three columns — Session | Today | All Time:

```
SESSION              TODAY                ALL TIME
MTM P&L:  +$2.11    Realized: +$8.40    Realized: +$38.42
Cash P&L: +$14.23   Fills:    847        Fills:    12,480
Fills:    847        Cancels:  3,201      Markets:  23
Uptime:   94.7%     Adverse30: 18%       AvgMkout: +0.3¢
```

### Per-market breakdown table

New collapsible section below the active markets panel. Sorted by lifetime realized P&L
descending.

```
MARKET PERFORMANCE (lifetime)
Market               Fills  Realized P&L  Cash P&L  Mkout30   Adverse%
Seoul temp 15°C+      240      +$5.40      +$4.10    +0.3¢      14%
London temp 16°C-     180      +$2.11      +$1.80    +0.1¢      19%
Iran regime 2027        0       $0.00       $0.00      —          —
```

### Data flow

- `SESSION` column — existing `MakerState` in-memory values (unchanged)
- `TODAY` column — `maker_lifetime.json["by_date"][today]` + current session delta
- `ALL TIME` column — `maker_lifetime.json` top-level totals + current session delta
- Per-market table — `maker_lifetime.json["by_market"]` + current session fill history

All recomputed in existing `dashboard_loop` every 2s. No new polling task.

New fields added to `MakerDashboardState`:
- `today_fills`, `today_realized_pnl`, `today_cash_pnl`, `today_adverse_rate`
- `alltime_fills`, `alltime_realized_pnl`, `alltime_cash_pnl`, `alltime_markets`
- `by_market: list[dict]` — one entry per token with lifetime stats

## Log Cleanup (pre-restart)

Before restarting the bot, the following files are cleared to start fresh with clean data:

**Logs** — all `logs/*.log` and `logs/*.log.*` (rotated backups)  
**Fill data** — `fills_markout.jsonl`, `fills.jsonl.bak.*`  
**Runtime** — `runtime.stdout.log`, `runtime.stderr.log`

`positions.jsonl` and `fills.jsonl` (scanner/taker bot) are NOT cleared — they belong to
the directional trading bot, not the maker.

A `scripts/clean_logs.sh` script handles this safely (maker_data/ is never touched).
